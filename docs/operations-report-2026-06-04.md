### 2.3 差异化定位

MD2X 有三个不可替代的卖点：

1. **X Articles 长文专用** — 不是 Thread 工具，是针对 X Articles 富文本编辑器优化的 Markdown→Clipboard 工具
2. **代码块→PNG 图片** — 解决了 X Articles 不支持代码格式化的核心痛点，竞品都没有
3. **免费+开源+纯浏览器端** — 零门槛、零数据外泄、零注册，隐私敏感用户的首选

## 四、市场需求与趋势

### 4.1 X 平台趋势

- X Articles 长文支持已达 25,000 字符，写作需求上升
- 前 280 字符作为"钩子"决定用户是否展开，标题/开头优化至关重要
- 长文+Thread 混合策略成为创作者标配
- 代码/技术类长文在 X 上的需求量持续增长（AI/编程话题热度）

### 4.2 用户画像

| 用户类型 | 需求 | 当前满足度 |
|----------|------|------------|
| 技术博主 | 代码+图表→X Articles | ★★★★☆ |
| 内容创作者 | Markdown 写作→快速发布 | ★★★☆☆ |
| 隐私敏感用户 | 本地化、不注册 | ★★★★★ |
| 多语言写作者 | 中英文切换 | ★★★★★ |
| Thread 创作者 | 长文拆 Thread | ★★★☆☆ |

### 4.3 市场空白

1. **X Articles 专用编辑器** — 市场上几乎没有专注 X Articles 长文的编辑器，大部分工具围绕 Thread
2. **代码友好型发布工具** — 开发者群体庞大，但缺乏将带代码的技术文章流畅发布到 X 的工具
3. **开源 + 自部署** — 团队/企业可能需要在自有域名部署

## 六、可立即执行的具体需求

以下 6 个需求已经过技术可行性验证，可提交开发：

### 需求 #1：补充 h4-h6 标题支持

- **文件**：`lib/markdown.ts`
- **改动**：`headingPattern` 正则 `/^(#{1,3})\s+(.+)$/` → `/^(#{1,6})\s+(.+)$/`，类型 `1|2|3` → `1|2|3|4|5|6`
- **预览**：`components/article-preview.tsx` 增加 h4-h6 样式
- **工作量**：~0.5 天

### 需求 #2：支持斜体语法

- **文件**：`lib/markdown.ts` — `parseInline` 函数
- **改动**：token 类型增加 `italic`，正则增加 `*italic*` 匹配（注意与 `**bold**` 区分）
- **预览**：`article-preview.tsx` — `<em>` 元素样式
- **工作量**：~0.5 天

### 需求 #3：支持引用块语法

- **文件**：`lib/markdown.ts` — `ArticleBlock` 增加 `blockquote` 类型
- **改动**：新增 `blockquotePattern = /^>\s?(.+)$/`，连续 `>` 行合并
- **预览**：`article-preview.tsx` — `<blockquote>` 样式渲染
- **工作量**：~0.5 天

### 需求 #4：支持图片语法

- **文件**：`lib/markdown.ts`
- **改动**：`ArticleBlock` 增加 `image` 类型，`parseInline` 增加 `![alt](url)` 匹配
- **预览**：`article-preview.tsx` — `<img>` 标签
- **工作量**：~0.5 天

### 需求 #5：分栏可拖拽调整

- **文件**：`components/editor-page.tsx`
- **改动**：将现有 `.cursor-col-resize` 占位元素改为可响应 `mousedown/mousemove/mouseup` 的拖拽手柄，动态调整左侧 `grid` 列宽
- **工作量**：~1 天

### 需求 #6：导入/导出 .md 文件

- **文件**：`components/markdown-editor.tsx` 或 `editor-page.tsx`
- **改动**：导入按钮（`<input type="file" accept=".md">`）读取文件；导出按钮（`Blob` + `URL.createObjectURL` 下载）
- **工作量**：~0.5 天
