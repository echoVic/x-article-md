## Excluded (noindex / client-only)

- `/offline` — generated by PWA, noindex, no OG.
- Blog detail pages (`/blog/[slug]`, `/zh/blog/[slug]`) — already have per-post dynamic OG images from prior batch; not in scope.

## twitter:site / creator

- `twitter:site = @echo_vic` — set at groupBaseMetadata (site-level). Evidence: `echo-vic-attribution.md`.
- `twitter:creator` — NOT set globally. Per-post creator only filled when frontmatter explicitly names the author.

## Implementation notes

- Each non-blog page has a colocated `opengraph-image.tsx` (edge runtime, 1200x630, paper background `#f7f5ef`, page-specific title).
- `twitter-image.tsx` re-exports the same generator (Next auto-mounts both og:image and twitter:image).
- Removed hardcoded pre-hash `twitter.images` from `buildPageMetadata`, `buildFeatureMetadata`, `buildCompareMetadata`, and `/zh/blog` page — Next now auto-resolves to the hashed route.
- `/privacy` has its own OG card (reuses home visual, "Privacy Policy" headline).

## Artifacts

- `og-contact-sheet.png` — 4x5 contact sheet of all 19 images.
- `og-images-verified.json` — per-route og/twitter URL, HTTP status, dimensions, SHA-256 from `verify-og-images.py` run against a local `next start`. Individual per-route PNGs are reproducible via that script and are not committed to the repo.
